# Report storage

Supabase owns operational data, events/tasks, staff assignments, immutable breakfast/housekeeping report snapshots, and shift report drafts/final reports.

Breakfast and housekeeping pages have an explicit Save report action and show their latest 30 saved versions. Copy/Print/WhatsApp by itself does not mark a report delivered or save a version. Shift reports are saved through Save draft or Confirm close.

The owner selected these existing destinations for Tours and Income:
- BOOKINGS INCOME: https://docs.google.com/spreadsheets/d/1cWSj5UfRDeME9nnYVp3N_DmkmN500FeFYcKAQr_jz6E/edit
- BOOKED TOURS: https://docs.google.com/spreadsheets/d/14CZDE7UpuA7jVgNjcgfpc6vNVccS2bTt6BswY1UhJX8/edit

Status: export built (features/sheets, migration 0027). New tours and income are queued in google_sheets_outbox and sent right after each save (next/server after()) plus a daily Vercel Cron (/api/sheets/flush, protected by CRON_SECRET) as a catch-up. Each row goes to the MONTHLY tab of its date - Spanish month in capitals + year, no space, no accents: SEPTIEMBRE2026, OCTUBRE2026 (tours use TOUR DATE, income uses DATE). Existing tabs are matched loosely (case, spaces and accents ignored; "SETIEMBRE 2026" counts as SEPTIEMBRE2026). A missing tab is created automatically with the header row (frozen); an empty tab gets the header row; a tab with different headers is refused. Rows are APPENDED under the tab's header row, which is verified first (BOOKED TOURS: TOUR DATE | TOUR OPERATOR | TYPE OF TOUR | GUEST NAME/PAX QTY | TOTAL TOUR | TOTAL COMISSION | STATUS | PAYMENT METHOD | BOOKED BY; BOOKINGS INCOME: CATEGORIES | TOTAL | DATE | DESCRIPTION | CLIENT | SOURCE OF PAYMENT | RESERVATION DATE). Columns are matched BY HEADER NAME (case and spaces ignored, so "GUEST NAME/ PAX QTY" matches) wherever they sit in the header row; extra columns such as COMPROBANTE # or "Column 1" are allowed and never written - a new row leaves them empty and a tour update leaves what staff typed there untouched. A tour whose status changes is re-queued and its existing row is updated, not duplicated. Income CATEGORIES is the stored booking channel (Directo / Booking.com / Expedia / Simple Booking / Hostelworld, or one set on the Room Board), blank when there is none - never the internal category. Only settled income is sent; reversals are negative rows; unpaid entries are skipped. USD amounts are numbers, CRC amounts are written as "CRC n" text so sheet totals never mix currencies. Everything queued before 2026-09-24 was marked skipped (the sheets already hold that history). Tour payment method is left blank because the travel office handles payment.

Shift reports are generated from saved records by a deterministic template (no AI, no external API); see docs/shift-report-activation.md.
